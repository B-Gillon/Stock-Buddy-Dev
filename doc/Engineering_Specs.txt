

=====================================================================
SECTION 24 — PUBLIC-FACING FLOW (REQUEST ACCESS)
=====================================================================

Stock Buddy has a public-facing entry point at stock-buddy.brandongillon.com
that is separate from the Shopify-embedded app flow.

### Root route behavior (src/app/page.jsx)
- If Shopify params (host + shop) are present → redirect to /dashboard
  (merchant is inside the Shopify Admin iframe)
- Otherwise → redirect to /request-access
  (public visitor landing on the site)
- InstallPage.jsx is no longer rendered at the root. It exists in
  src/app/components/ but is not currently used. Do not delete it —
  it may be repurposed later.

### Approved tester install flow
There is no public install form. When a beta tester is approved, they
are sent a direct OAuth URL:
  https://stock-buddy.brandongillon.com/api/shopify/install?shop=their-store.myshopify.com
This URL only works for the exact shop domain in the query param.
Shopify enforces this during the OAuth flow.

### Request-access flow (two pages)

Page 1 — Intro (src/app/request-access/page.jsx)
- Rendered by: src/app/request-access/components/RequestAccessIntro.jsx
- Shows: app description, private beta notice, feature list (2x2 mini cards)
- Actions: "Request Access" → navigates to /request-access/form
           "Have Questions?" → opens ContactModal (inline, no page nav)

Page 2 — Form (src/app/request-access/form/page.jsx)
- Rendered by: src/app/request-access/form/components/RequestAccessForm.jsx
- Collects: store URL, contact info, business profile, current process,
  beta participation intent, and two required acknowledgement checkboxes
- Submits to: POST /api/request-access
- On success: shows confirmation with submitter's email address
- Back button returns to /request-access

### Contact modal (RequestAccessIntro.jsx)
- Inline modal, not a separate page or route
- Fields: Name, Email, Message
- Submits to: POST /api/contact
- On success: shows confirmation, then closes
- Does NOT use mailto — avoids OS email client dialogs

### API routes

POST /api/request-access (src/app/api/request-access/route.js)
- No auth required (public form)
- Validates required fields: store_url, contact_name, contact_email,
  understands_private_beta, agrees_no_share_link
- Inserts into access_requests table with status = 'pending'
- Returns { success: true } on success

POST /api/contact (src/app/api/contact/route.js)
- No auth required (public form)
- Validates required fields: name, email, message
- Sends plain-text email to hello@brandongillon.com via SMTP
- Sets replyTo to submitter's email so replies go directly to them
- Uses same nodemailer transporter pattern as sendPOEmail.js

### Beta tester approval workflow (manual, no automation)
1. Review submissions in Supabase: access_requests table
2. Update status to 'approved' or 'rejected' and set reviewed_at
3. Manually add approved applicant to beta_testers table
4. Send them the direct OAuth URL for their shop domain
5. After they install, their tenant record is created automatically
   and the admin page resolves their tenant_id via shopify_domain match

### Key files
